# GitHub handle request

Asks accepted participants who are missing a valid public GitHub username to send one before kickoff.

**When:** T-3w, after confirmations are in; one follow-up at T-1w if needed.

**Sent by / owner:** Program organizer or a Team Lead.

**Audience:** Accepted participants with a blank or invalid GitHub username (one email, all recipients in BCC).

## Template

```text
Subject: Quick ask: we need your public GitHub username

Hi!

You're in the Sustaining Open Source Series 🎉 and we're getting everything ready for kickoff on [Start date].

One quick thing: we don't have a valid public GitHub username for you. Either it was left blank on your application, or what we have isn't a public github.com account.

Could you reply with your public GitHub username as soon as possible?

A few notes:
- It needs to be your public github.com account, not an internal company GitHub account. All series contributions happen in the open.
- Don't have one yet? It's free to create at github.com/signup. Just send it over once you do.
[Company-specific: - Follow [Company]'s guidance on linking your work email to your GitHub profile: [Guidance link]]
- Already replied? Thank you, you can ignore this!

We use your username so mentors can find and support your work, and so we can celebrate your contributions during the series.

Thank you!

Best,
The Sustaining Open Source Series team
```

## How to use

- Check every submitted username resolves to a public github.com profile before sending; include anyone whose entry is blank, an internal link, or a URL that doesn't resolve.
- Any public profile is fine, including one that looks like a work identity.
- Put all recipients in BCC.
- Record handles in the participant tracker as they arrive.

## Notes for alignment

- **Recommendation:** Public. Only the attribution guidance line is company-specific.
- **Company-specific parts:** guidance on linking a work email or attribution.
